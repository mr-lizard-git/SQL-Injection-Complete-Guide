# References and Further Study

These sources support the techniques and defensive guidance in this project. Follow the target lab's current instructions and keep practice within its authorized environment.

1. PortSwigger, [SQL injection](https://portswigger.net/web-security/sql-injection) — overview and guided labs.
2. PortSwigger, [SQL injection UNION attacks](https://portswigger.net/web-security/sql-injection/union-attacks) — column-count and compatible-type requirements.
3. PortSwigger, [Blind SQL injection](https://portswigger.net/web-security/sql-injection/blind) — boolean and timing techniques.
4. PortSwigger, [Burp Proxy documentation](https://portswigger.net/burp/documentation/desktop/tools/proxy) — intercepting and inspecting HTTP traffic.
5. OWASP Cheat Sheet Series, [SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html) — parameterized queries, allow-lists, and defense in depth.
6. OWASP, [Web Security Testing Guide: Testing for SQL Injection](https://owasp.org/www-project-web-security-testing-guide/) — structured testing guidance.
7. Damn Vulnerable Web Application, [DVWA repository](https://github.com/digininja/DVWA) — intentionally vulnerable application for local training.

The guide paraphrases these concepts and uses original explanations and diagrams; it does not reproduce source tutorials. Database syntax differs by engine, driver, version, and configuration. Validate technical details against the documentation for the actual authorized lab environment.
